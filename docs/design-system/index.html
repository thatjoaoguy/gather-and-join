Join and Create share visual weight. Once connected, replace the lobby with room details. This specification shows both states side by side.

Feedback you can trust

Submitting shows “Joining…” or “Creating…” and prevents duplicate submissions. Failures appear next to the code. Copy feedback follows a successful clipboard write.

Host is a room role

Guest onboarding / proposed

A shared invite should carry the connection address and room code so guests can install and join. The current app requires each guest to set an address; this needs implementation beyond styling.

Ask when it matters

Explain microphone access before the browser prompt. Camera access stays separate. When blocked, show a plain-language explanation and a route to Chrome’s extension permissions.

Host once, welcome everyone

The person running the server owns startup and sharing its address. Guests should not see deployment commands or network jargon in the main room flow.

Keep room and server lifetimes distinct

Leaving a room ends your participation. Stopping the server can disconnect everyone. A laptop hosting the server must remain awake.

Save feedback is specific

“Address saved. Applies to your next room.” Never imply that an address was tested just because it was stored.

Host help / content to design next

A dedicated hosting guide can explain server startup and sharing. This specification keeps connection entry compatible with today’s extension.

Stable presence

Keep people in a stable order: you first, then arrival order. No reshuffling when someone speaks. No moving gradients, idle bounce, or pulsing borders during playback.

Protect the picture

Reserve space beside the player in normal and fullscreen modes. Current implementation uses 240px; this study proposes 180px on wide windows. Narrow viewports need a compact rail and overflow for larger rooms.

A static purple border and “Speaking” label appear together. Production voice activity signaling is not currently exposed to this UI; the example is a visual proposal, not an existing capability.

05 / Components & motion

A response to every action.

Responsive controls, readable state labels, and a small amount of movement. Disabled controls stay still. Feedback remains available with reduced motion.

Buttons & control states

Hover, press, or tab through the controls.

Enter the six-character code from your friend.

Focus: 3px light-purple outline with a 4px offset. Errors include a written explanation. Component boundaries use a stronger border than decorative panels.

Playful on purpose.

360ms arrival with a 10px rise and slight overshoot. Button hover lifts 2px; press scales to 96%. Use arrival motion once when a panel or confirmation appears.

Alex joined. Your room is ready.

System reduced-motion preferences always win. Reduced motion removes movement and transitions; text feedback appears immediately. Technical reconnect retries never bounce the UI.

Color feedback: 120ms ease
No looping decorative animation.

06 / Feedback & recovery

Keep the room informed.

Show messages where the issue can be resolved. Persistent problems remain visible until resolved; successful acknowledgments do not obscure the show.

You’re now the room host

You can choose the next episode. Everyone can still play or pause.

A role update is informational, not an error.

Connection restored

You’re back with your friends. Your room is ready again.

Acknowledge briefly, then return to a neutral connected state.

Your connection is unstable

You’re still in the room. Audio or video may briefly cut out.

Keep visible while quality is degraded. This requires a reliable quality signal.

Room not found

Check the code with your friend, then try again.

Keep the name and code. Offer a purple “Try again” action after failure.

Reconnecting to your room…

Your connection dropped. We’re trying again.

Keep participants in place and mark their connection state. Do not display “Connected” until confirmed.

Alex is buffering

The show is paused. Press play when everyone is ready.

Use the streaming player to resume. No automatic resume.

Your room is watching another episode

Open the room’s episode to catch up with your friends.

Action label: “Go to episode”. Only offer it when the room provides a valid watch URL.

Microphone access is blocked

You can stay in the room. Open setup to allow your microphone.

Camera permission has its own equivalent message.

You’re the first one here

Share the room code and settle in.

Empty state: show your own tile, the code, and media controls. Never use a blank participant list.

07 / Implementation notes

One system, three surfaces.

Approved visual system: Quicksand, round & playful, equal purple/red balance, and four semantic colors. Layout reference values guide implementation; product dependencies are identified below. This specification does not change the extension.

SurfaceCurrent sourceApply
Popupapps/extension/entrypoints/popup/Tokens, lobby and room layouts, labeled media toggles, inline recovery.
Setupapps/extension/entrypoints/options/Device permissions, optional ducking, connection settings, save feedback.
Participant HUDapps/extension/lib/sidebar/sidebar-view.tsEmbed tokens within the shadow root, isolate host-page styles, preserve fullscreen mounting and live streams.

Accessibility acceptance

All controls work with keyboard input and visible focus. Toggles announce their state. Validation connects inputs to help text. Status messages use polite live regions. Target 4.5:1 text contrast and 3:1 essential control boundaries. Do not rely on hue alone.

Local fonts

Bundle Quicksand with the extension and declare it inside each relevant surface. This specification loads local font files, so it works offline. Font licenses are included alongside the files.

Requires product work

Invites carrying a server address; speaking-state signaling; remote mute indicators; responsive participant overflow. Do not treat the visual mockups as evidence those capabilities already exist.

Implementation reference

Read the design-system reference for approved tokens, usage, files, validation, and integration boundaries.

The brand uses a horizontal Softer heart lockup with purple “Gather”, a white ampersand, and red “Join”. The lettering is outlined in SVG for consistent rendering. Avoid stacking the mark above the wordmark; use the standalone mark for compact placements. Status symbols shown here support meaning; a broader icon library and illustration system remain outside this specification.
