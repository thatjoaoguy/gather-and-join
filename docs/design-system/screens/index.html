Design system / Screens

The extension, restyled.

Every surface the extension actually renders, in every state its code can produce, at true size. Each mock lists the snapshot fields that drive it, so the popup, setup page and participant HUD can be implemented against these directly. Static: nothing here connects to anything.

Popup frames are 360px wide with 24px padding, as specified.Setup is a full tab at 720px.The HUD is shown at the current 240px and the proposed 180px.
01 / Popup · Lobby

Before the room.

Shown while snapshot.room is null. One flow at a time: a Join / Create switch keeps purple and red present with equal weight, but only one action is on screen. Join is disabled until the code is six valid characters. Device permissions and the server are visible here, with their state, so nobody discovers a blocked microphone after joining.

Lobby / First run, nothing set up360px

A little closer.
Even from afar.

Let’s get you set up

Your microphone, your camera if you want one, and the address of the server someone in your group is hosting. Once, and you’re done.

Setup takes a minute and holds for every party after this one.

Drives: no serverUrl has ever been saved and the built-in default is not answering — firstRun() in lib/setup-state.ts. Nothing is wrong yet, so nothing is red: the join and create controls are hidden rather than disabled, because there is nowhere to join, and the unreachable-server callout is suppressed. The readiness list is gone too — before setup there is nothing to be ready for, and the three states belong to the page the button opens. The moment an address is saved, or the default answers, this becomes the ordinary lobby. A fresh install also opens the setup page by itself.

03 / Setup page

Make yourself comfortable.

The options page: the first run, and afterwards the place to change any of it. It opens by itself on install, from the popup, or in grant mode from an "Allow" action. Three numbered steps — microphone, camera (optional), connection address — with a block at the top saying what is still outstanding, then the ducking switch and diagnostics.

04 / Participant HUD

Present, without taking over.

The sidebar the content script mounts beside the player, in a shadow root so the host page cannot restyle it. You first, then arrival order, order never changes. Live video fills a tile when a camera is on; otherwise the initial and name. Fonts and tokens are embedded in the shadow root.

Drives: participantsFrom(snapshot, { selfFirst: true }) for the tiles, loopback.streamFor(peerId) for whether a tile shows video. Self video is mirrored; remote video is not. Name labels sit on a dark backing so they read over any picture. A muted participant gets a small mic-off badge in the warning tone at the top-left of their tile; it needs mute state on the wire (a media frame or a data-channel flag), which does not exist yet, so today only your own tile could show it. Speaking is the tile border turning purple, nothing else: no label, no motion, so it reads in the corner of the eye without pulling focus from the show. The offscreen document already measures each peer’s audio level for diagnostics (RemoteMedia.audioPeaks) and runs a speech detector on your own mic for ducking, so a speaking flag per participant in the snapshot needs no protocol change, only a threshold and a short hold so it does not flicker.
